Overview

Ship one remote Jarvis (Hermes profile + sibling Docker image + durable volume): morning research→email digest, day-1 Slack DM/home chat on the same brain, no local dual install. Land shared three-lane config doctrine and parallel Kevin doc/pack filters so product packs do not cross-contaminate skills.

Intended changes (highlights)

Product pack filter: Kevin pack currently cp -a dist/hermes/skills wholesale. After jarvis skills exist, both packs must allowlist/denylist so factory and CoS skills never bake into the wrong image.
Entrypoint: sibling of kevin entrypoint with profile name jarvis, skills /opt/jarvis/skills, no required product-repo mount.
State: $HERMES_HOME/profiles/jarvis/state/projects.md — adaptive lane; not distribution_owned.

Plan-time decisions

  • Image name: jarvis-hermes (sibling of kevin-hermes)
  • Profile path: hermes/jarvis-profile/
  • Sibling Docker files (not multi-ARG Dockerfile v1)
  • Email: SMTP env names + send helper in ritual (no in-repo email product today)
  • Slack: home channel + DM, allowlisted user(s), Socket Mode
  • Skills root under src/jarvis/; product stamp jarvis
Key insight: Land pack allowlists in the same change as the first jarvis skill (D4/D7), before D3 image bake — otherwise kevin-hermes would ship CoS skills by accident.
